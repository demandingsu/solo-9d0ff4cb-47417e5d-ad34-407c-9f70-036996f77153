# 园区总表累计读数 → 月度用量发布平台

把园区总表的**累计 kWh 读数 CSV** 整理成月度数仓可用的**用量明细与月合计**的
FastAPI + SQLite 网页应用，支持补传重发、异常读数更正、整批拒收与不可变版本发布。

## 业务规则实现

| 需求 | 实现 |
| --- | --- |
| 非有限值不得入库 | 普通上传的累计 kWh 含 `NaN`/`Infinity`/`-Infinity` 时，解析阶段即**整批拒收**，一条都不入库 |
| 同刻同内容重传不重复入库 | `(ts, period_no)` 唯一；累计值相同则幂等跳过并计数 |
| 同刻异内容 | 整批回滚拒收，库内读数不变，批次表留拒收记录；正常有限读数的异值重传同样拒绝 |
| 异常读数恢复 | 「异常读数更正」页上传同三列更正 CSV，仅可把**已入库的非有限读数**替换为有限值 |
| 更正后单调性 | 替换后的读数与库内其他全部读数合并，按周期逐对复核时间单调性，倒退则整批拒收 |
| 保留原批次与更正来源 | 读数原地更新（id、原 `batch_id`、入库时间不变）；`reading_corrections` 记录原批次、更正批次、替换前后值 |
| 更正原子性 | 整流程一个事务：任一更正无效或写入失败，回滚不留部分读数，也不留更正记录（网页拒收仅留一条拒收批次审计痕跡） |
| 同周期读数倒退 | 合并库内+本批按时间排序逐对校验，发现倒退整批拒收 |
| 仅相邻同周期算差额 | 相邻两次读数 `period_no` 相同才计算 `后笔-前笔`；换表跨周期跳过、不估算 |
| 差额归属月份 | 归入**后笔读数所在 UTC 月** |
| 两月一次发布 | 页面选择相邻两个 UTC 月，一个事务生成明细 + 月合计新版本 |
| 版本指纹一致性 | 发布在 `BEGIN IMMEDIATE` 事务内对**当前全部读数**快照计算并固化 SHA-256 指纹；补传/更正与发布交错时，同一版本的明细、月合计、指纹必然来自同一已提交读数状态 |
| 不可装载版本标记 | 含非有限（NaN/Infinity）用量的版本 `is_loadable=0`：页面与下载 CSV 均标明“不可用于装载”，但永久保留可下载；更正后重新发布得到可装载新版本 |
| 上传/更正失败不留痕 | 整批事务，任何校验失败都 rollback |
| 发布失败不留新版本 | 版本头、明细、合计同一事务，失败 rollback（含故障注入自测） |
| 旧库平滑升级 | 启动时幂等迁移：补 `kind`/`corrected_cnt`/`is_loadable` 列、建更正表，并按明细内容回填历史版本的可装载标记 |

### 关于历史上的 Infinity 故障

早期版本未拦截非有限值，网关 CSV 里的 `Infinity` 会作为 REAL 进入 `readings`；
两笔 Infinity 的差额是 `inf-inf=NaN`，而 Python sqlite3 绑定 NaN 时写为 NULL，
撞 `version_details.usage_kwh NOT NULL`，导致月度发布整体失败；此时同刻重传
有限值又被“同刻异内容”规则拒收，读数无法自救。本版本：

1. 普通上传从此拒收一切 NaN/Infinity；
2. 已入库的非有限读数只能经更正通道替换为有限值；
3. 发布遇到仍未更正的非有限读数不再崩溃——NaN 差额落库前规范化为可存储的
   Infinity REAL，版本完整生成但标记为**不可装载**，更正后重发即可。

## CSV 格式

UTF-8 编码，三列（表头中英文均可，顺序不限）：

- UTC 时间：`utc_time` / `ts`，必须带时区，如 `2026-01-01T00:00:00Z`
- 表计周期号：`period_no`，整数
- 累计 kWh：`cumulative_kwh`，**有限数值**（不接受 NaN/Infinity）

普通上传示例见 `examples/sample_readings.csv`；
更正示例见 `examples/sample_correction.csv`（同样三列，每行对应一条待更正的异常读数）。

## 启动（Docker Compose）

```bash
docker compose up --build -d
# 打开 http://localhost:8000
```

SQLite 数据保存在命名卷 `energy_data`（容器内 `/data/energy.db`）。
容器内 `init_db()` 会在启动时自动建表并对旧库做幂等迁移。

## 页面

- `/` 概览（读数/非有限待更正/更正/批次/版本统计）
- `/upload` 普通 CSV 上传（非有限值整批拒收）、上传批次接受/拒收记录
- `/corrections` 异常读数更正：待更正清单、更正 CSV 上传、更正批次与溯源记录
- `/readings` 当前读数、更正溯源、差额预览、读数状态指纹
- `/publish` 选择相邻两个 UTC 月发布新版本（含非有限读数时提示将不可装载）
- `/versions` 历史版本（指纹是否匹配当前读数、可装载标记一目了然）
- `/versions/{id}` 版本明细、月合计与 CSV 下载（不可装载版本的 CSV 首行为 `# WARNING ... NOT LOADABLE`）

## 自测要点

`tests/` 覆盖：幂等重传、异内容拒收、读数倒退拒收、跨周期不估算、
月界差额归属、迟到补传同时改变两个月、补传与发布交错的版本一致性、
发布故障注入回滚（不留新版本）、旧版不可变；以及异常恢复专项——
NaN/Infinity 整批拒收、遗留 Infinity 不再使发布崩溃、更正替换与溯源、
更正的各类无效情形拒收且无部分写入、更正单调性复核、不可装载标记与下载警示、
更正/补传/发布并发交错一致性、旧库迁移回填。
